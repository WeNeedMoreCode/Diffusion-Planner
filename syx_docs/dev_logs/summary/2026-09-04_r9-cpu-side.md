# 2026-09-04 R9：CPU 段削减——host 侧直通 + 地图不变量缓存，RC 102.5→90.0ms

> R8 后两板 fwd 同价（~11ms），剩余差距全在 CPU 段。本轮两项：①to_tensor 免上卡（DP_OM 下 adapt 产出直接留 host）②roadblock 修正的地图不变量缓存（严格等价）。RC 102.5→90.0、DUO 77.5→70.5，双板 50 场景 0.9171 三轮逐位一致。分步实测：①在 RC -6.2（比 DUO 大——RC 搬运/sync 更贵 1.46×）、②在 RC -6.3（np 转换被 CPU 1.34× 放大）。期间两个概念澄清（dispatch/launch/搬运三者不同、口径纪律）与一次"SoC 共享内存"误判（被分步实测推翻）。

## 事实：①to_tensor 免上卡

R8 前数据流有纯粹浪费的中转：adapt 尾 `to_tensor` 把输入搬上 NPU（H2D ~1.4ms）→ OmBody 每次调用又把全部输入逐个搬回 host（bench_om 实测 d2h ~2.2ms/步）。DP_OM 下计算全在图内（aclruntime 交换 host buffer），卡上中转纯是搬运。改动：`planner.py` DP_OM 时给 `observation_adapter` 传 `device="cpu"`（上卡点仅 `convert_to_model_inputs` 一处 `.to(device)`），decoder forward 的 mask 小 op 顺势转 CPU（再削 RC 发射）。bench_step（DUO）：sum 11.68→10.74（enc_om -0.4=d2h 消失、prep -0.5=mask CPU 化）。

**板间收益不对称（RC 实测 -6.2 vs DUO 反推 ~-2.3）**：①在 RC 的收益反而更大——与 R7 证据方向一致（RC 的 sync 往返 114.9 vs 78.9us = 1.46×，搬运类操作 RC 更贵）。**期间走过一次弯路（记录防重蹈）**：RC 首测"没反应"实为内层未 pull（跑的还是 R8 状态），当时据此编了"SoC 共享内存→搬运便宜→①在 RC 无收益"的解释——被分步实测（reset 到 `301d182` 单测①：50 场景 102.5→96.3）推翻。教训有二：①**基线必须确认被测代码真的生效**（git log 对版本，别拿误测数据解释现象）；②对"没反应"的现象，先怀疑测量、再造理论。另：5 场景口径（-3.1）与 50 场景口径（-6.2）差一倍，中位数的中位数在 5 样本上方差大，**性能对账一律用 50 场景同口径**。

## 事实：②roadblock 修正的地图不变量缓存（严格等价）

`route_roadblock_correction`（dp-adapt 的 route 段，R8 时 10.5-10.6ms）每步重复做两件地图不变量工作：
1. candidates 误差循环里逐 lane 把 `StateSE2` python 列表转 np.array（`np.array([s.point.array for s in discrete_path])`）——几何不变，每步重转
2. 对相同的 mission route ids 逐个 `get_map_object` 重建 dict

改动（`roadblock_utils.py`）：`_LANE_GEOM_CACHE`（lane.id → (离散点 [N,2], headings [N])）+ `_ROUTE_BLOCK_CACHE`（route ids 元组 → block dict）。**无任何量化近似，不碰验收口径**。防跨图撞 key：单槽 `_CACHE_MAP_NAME`，`map_api.map_name` 变化时整体清空。修正函数对 `list(dict.values())` 的后续原地修改不动缓存对象，安全。

**route 段"两板同价"的观察与修正**：R8 时 route 总时长两板相同（10.5/10.6ms），据此预判"缓存收益按 DUO 原值 -4.7 兑现、不随 CPU 比放大"——**②实测推翻**：RC 实际 -6.3。解释：总时长同价不等于构成同价，段内 np 转换部分在 RC 上被 CPU 1.34× 放大（查询部分占比小），缓存砍掉的恰是转换部分，收益 = 4.7×1.34 ≈ 6.3 ✓。教训：**段级同价推不出段内构成同价，缓存收益看被砍部分的板间比**。

## 概念沉淀：dispatch / launch / 搬运三者不同（用户提问触发）

| | 是什么 | 何时发生 | 测法 |
|---|---|---|---|
| dispatch（派发） | host 侧"决定做什么"（Python→torch 派发层校验/选 kernel） | 每次 tensor op，目标 CPU 也照付 | cpu_micro |
| launch（投递） | "执行这个 kernel"的工单写进 NPU 命令队列，固定邮费 | 只在目标 NPU；计算与 memcpy 任务都走 | npu_micro_stream − cpu_micro |
| 搬运（`.to(device)`） | 数据字节的物理移动，成本=字节÷带宽，PCIe 或片内 | 只在换设备 | bench_om mixed 的 d2h/h2d |

一次 `.to("npu")` 三者同时发生（它是 op → dispatch；memcpy 也是任务 → launch；然后字节传输）——易混点。三者也能单独出现：计算 op=dispatch+launch 零字节；CPU op=仅 dispatch。
